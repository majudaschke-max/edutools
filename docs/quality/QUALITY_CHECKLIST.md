# Quality Checklist

Die Checkliste wird vor Abschluss einer Funktion geprüft. Nicht anwendbare Punkte werden bewusst als solche dokumentiert.

## Didaktik

- [ ] Unterstützt die Funktion ein konkretes Lern- oder Unterrichtsziel?
- [ ] Vermeidet sie Ablenkung und unnötige kognitive Last?
- [ ] Gibt sie hilfreiche, nicht wertende Rückmeldung?

## UX

- [ ] Ist der nächste sinnvolle Schritt unmittelbar verständlich?
- [ ] Sind leere, Lade-, Erfolgs- und Fehlerzustände berücksichtigt?
- [ ] Verwendet die Oberfläche klare, aktive Beschriftungen?
- [ ] Funktioniert der Ablauf auf Smartphone, Tablet und Desktop?

## Design

- [ ] Werden Design Tokens statt fest codierter Werte verwendet?
- [ ] Entspricht die Gestaltung dem ruhigen EduSoft-Charakter?
- [ ] Bleiben Hierarchie, Abstände und Zustände konsistent?
- [ ] Ist Farbe nie das einzige Bedeutungssignal?

## Accessibility

- [ ] Ist semantisches HTML eingesetzt?
- [ ] Ist die Funktion vollständig per Tastatur bedienbar?
- [ ] Sind Fokuszustände sichtbar und Touch-Ziele ausreichend groß?
- [ ] Sind Labels, Kontraste und Fehlermeldungen verständlich?
- [ ] Wird reduzierte Bewegung respektiert?

## Datenschutz

- [ ] Werden nur notwendige Daten verarbeitet?
- [ ] Bleiben Daten standardmäßig lokal?
- [ ] Wurden Tracking, externe Dienste und personenbezogene Daten vermieden?
- [ ] Ist jede notwendige Ausnahme dokumentiert?

## Technik

- [ ] Sind Code, Konfiguration und Inhalte getrennt?
- [ ] Werden ungültige oder fehlende Daten verständlich behandelt?
- [ ] Gibt es keine kritischen Konsolenfehler?
- [ ] Sind neue Abhängigkeiten notwendig und begründet?

## Performance

- [ ] Werden nur notwendige Ressourcen geladen?
- [ ] Bleibt die Oberfläche auch auf schwächeren Geräten reaktionsfähig?
- [ ] Sind Dateigrößen und Ladeverhalten angemessen?

## Dokumentation

- [ ] Sind Anforderungen und Abnahmekriterien aktuell?
- [ ] Wurden relevante Architekturentscheidungen dokumentiert?
- [ ] Sind lokale Nutzung und bekannte Grenzen beschrieben?
